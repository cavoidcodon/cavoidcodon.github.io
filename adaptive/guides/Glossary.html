    About This Guide#

    This guide is the glossary of the whole series. It defines every acronym and every term once, for all guides, and each guide's own glossary uses the same wording. Definitions are based on the AUTOSAR Glossary (R25-11), the Platform Design and Software Architecture explanations, and the specifications of the clusters. Keep it at hand while you read the other guides.

    How to Read This Guide#

    This guide is for lookup. Chapter 1 lists the acronyms, Chapter 2 the terms, both in alphabetical order. The column Explained in names the guide, and where possible the section, that explains a term in detail: [Diagnostics Part 2, 9.7] means the Diagnostics Part 2 guide, Section 9.7. Guides are named by the short names listed on the main page, and Main page means the main page of the series.

    2. Glossary#

    Term Meaning Explained in
    Aging Deleting an event memory entry after a configured number of operation cycles without failure. Diagnostics Part 2, 9.7
    Clear Condition A condition that must be fulfilled for a DTC to be cleared; set by an application through ara::diag::Condition. AP only. Diagnostics Part 2, 7.3
    Confirmed DTC A DTC whose status bit 3 is set, after the configured number of failed operation cycles (confirmation threshold). Diagnostics Part 2, 8.2
    Debouncing Filtering of diagnostic monitor reports until a result is qualified as failed or passed; counter-based, time-based or inside the monitor. Diagnostics Part 2, 6.1
    Displacement Replacing a less important event memory entry by a new one when the event memory is full. Diagnostics Part 2, 9.6
    Enable Condition A condition that must be fulfilled for the reports of a diagnostic event to count; set by an application through ara::diag::Condition. Diagnostics Part 2, 7.2
    Event Combination Mapping several diagnostic events to one DTC, combined on storage or on retrieval. Diagnostics Part 2, 8.4
    Extended Data Record A record of mostly statistical data stored with a DTC, such as the occurrence counter or the aging counter. Diagnostics Part 2, 9.4
    Fault Detection Counter (FDC) The debouncing progress of a diagnostic event, from −128 (finally healed) to +127 (finally defective). Diagnostics Part 2, 2.3
    Indicator (diagnostic) A warning output, such as a lamp, linked to diagnostic events; drives status bit 7 of their DTCs. Diagnostics Part 2, 8.5
    Pending DTC A DTC whose status bit 2 is set: it failed in the current or the last operation cycle. Diagnostics Part 2, 8.2
    Proximity Challenge An SOVD mechanism that proves that a person is physically at the vehicle before an operation runs. Diagnostics Part 2, 13.4
    SOVD Gateway The edge node that routes SOVD requests from clients to the SOVD servers in the vehicle. Diagnostics Part 2, 3.4
    SOVD Lock Exclusive access of one SOVD client to an SOVD entity; excludes a UDS client in the extended session. Diagnostics Part 2, 12.5
    SOVD Server An SOVD endpoint in the vehicle. On the Adaptive Platform, Diagnostic Management is an SOVD server; each Diagnostic Server instance is a sub-component. Diagnostics Part 2, 12.1
    UDS DTC Status Byte The 8 status bits of a DTC defined by ISO 14229-1, such as test failed, pending and confirmed. Diagnostics Part 2, 2.2
    ≪atpSplitable≫ Stereotype of a property whose content may be spread over several files. Manifests, 3.7
    ≪atpUriDef≫ Stereotype of a reference whose path carries the information, even if the target is not on the Machine. Manifests, 1.2, Manifests, 9.4
    Abnormal Termination A process ended with an exit status other than 0, for example after a crash. EM, 2.5
    AbortHandler A function void() noexcept that ara::core::Abort calls, in reverse order of installation, before it ends the process Core, 10.4
    Access Control Decision The yes-or-no answer whether a requested operation is permitted. It is based on the identity of the caller and the Access Control Policy. IAM
    Access Control Policy A rule, bound to a target such as a service interface, that states which identity is needed to access it. IAM
    Access Permission (diagnostics) DiagnosticAccessPermission: the sessions, security levels, environmental condition and roles in which a diagnostic service, DID or routine may be used. Diagnostics Part 1, 7.3
    ActionList The ordered list of ActionListItems that a StateMachine executes when it enters a StateMachine State (meta-class StateManagementActionList). SM, 2.3
    ActionListItem One action of an ActionList, for example a Function Group State request, SYNC, Sleep or the start of an Agent. SM, 2.3
    Activation (update) The critical phase of a software update in which the new software is switched on and can still be rolled back. UCM
    Active subscriber An application that has called Subscribe on an event, field or trigger and has not called Unsubscribe. CM, 2.6
    Active update session The period from the accepted RequestUpdateSession to the end of StopUpdateSession, during which State Management supports UCM and keeps the machine available. SM, 2.7
    Adaptive Application Software that delivers a function. It consists of one or more Executables. It uses only ARA and the POSIX profile PSE51, so that it can be deployed on any Adaptive Platform. EM, 2.1
    Adaptive Platform AUTOSAR's software platform for high-performance ECUs with service-oriented communication and updatable software. The term means both the standard and an implementation of it. Main page, Platform Overview, 1.1
    Adaptive Platform Foundation The part of the platform that provides the fundamental functions, such as Execution Management, Communication Management and Persistency, as library-based APIs. Main page, Platform Overview, 3.3
    Adaptive Platform Services Standard platform services, such as UCM and State Management, that are provided as services over Communication Management. Main page, Platform Overview, 3.3
    Agent (State Management) A StateMachine that the Controller starts and stops; it controls the Function Groups of one Software Cluster. SM, 2.5
    Alive Indication One report of a checkpoint that is used for alive supervision. PHM, 6.2
    Alive Supervision A PHM supervision that counts the reports of a checkpoint in each reference cycle and checks them against an expected number with margins. PHM, 6
    APMC The M1-based target-configuration model with a definition side and a value side that replaces manifest content step by step. Manifests, 11.9
    Application Design The design-related part of the model: data types, service interfaces, persistency interfaces and other interfaces that an application uses, independent of any deployment. Manifests, 2.3
    Application ID The identifier of one process instance in log and trace messages, defined by DltApplication.applicationId. Log and Trace, 5.2
    ARA The AUTOSAR Runtime for Adaptive Applications: the standard C++ interfaces that the functional clusters provide to applications. Main page, Platform Overview, 3.2
    ARElement A model element that can be defined stand-alone in a package. Manifests, 2.4
    ARPackage A package of the model. It establishes a name space and is an open set: several files may contribute to it. Manifests, 3.2
    ARTI The AUTOSAR Run-Time Interface between build tools and debugging and tracing tools. The OSI defines ARTI trace messages for processes and tasks. Platform Overview, 7.10
    Async-signal-safe Safe to call from a POSIX signal handler. No ARA API is Core, 12.7
    Authenticator The (truncated) message authentication code that SecOC appends to a message. Secure Communication, 2.3
    Authenticity The property that data comes from the source it claims to come from. Cryptography
    Automotive API Gateway The functional cluster that gives clients access to selected vehicle data through VISS and VSS. Not covered by the series. Main page
    AUTOSAR XML (ARXML) The XML format in which AUTOSAR models, including manifests, are exchanged. Manifests, 3.1
    Backup (Persistency) The copy of all persistent data of a process that Persistency creates before an update; only one backup exists at a time. Persistency, 12.5
    Basic Software (BSW) In the Classic Platform, the infrastructure software of an ECU below the RTE: services, ECU abstraction, microcontroller abstraction and complex drivers. Platform Overview, 2.2
    Central storage The location where Persistency keeps the list of installed storages and the versions for one process (PersistencyCentralStorageUri). Persistency, 12.2
    Certificate An X.509 document that binds a public key to an identity and is signed by a certificate authority. Cryptography
    Checkpoint A point in the control flow of a Supervised Entity where the activity is reported to PHM, so that PHM can supervise its timing and order. PHM, 2.1
    Cipher Suite A set of algorithms for key exchange, authentication and encryption of a TLS connection, identified by an IANA number. Secure Communication, 6.4
    Class table The table of the TPS that lists the attributes of a meta-class with type, multiplicity and kind. Manifests, 3.8
    Classic Platform AUTOSAR's software platform for deeply embedded ECUs with high demands on predictability, safety and responsiveness. Platform Overview, 2.1
    Client A software entity that uses the services of a server. CM, 2.1
    Companion Process A small reporting process that reports kRunning on behalf of a non-reporting process once that process is really usable. EM, 5.4
    Compositionality The behavior of a component does not depend on the overall system load and configuration; an important property of deterministic systems. Platform Overview, 2.3.1
    ComSpec A qualification of the use of one element of an interface at one port, for example the initial value of a field. Manifests, 5.2
    Configuration class In the Classic Platform, the time at which a parameter is fixed: pre-compile time, link time or post-build time. Platform Overview, 2.3.4
    Constraint A numbered rule on the meta-model, cited as [constr_nnnn]. It must hold from its imposition time on; a model that violates it at that point is invalid. Main page, Manifests, 2.5
    Context ID The Log and Trace identifier of a logical group of messages within an application, for example TRCK of Fusion; platform clusters use reserved four-character IDs such as #COR Core, 12.5, Log and Trace, 5.3
    Continuation A callable registered with Future::then that runs when the result is ready Core, 9.5
    Contract version The version of the structure of a process's persistent data; when it increases, the application may migrate its data in the update callback. Persistency, 2.5
    Control message A DLT message with which a logging client controls the logging module, or the module's response. Log and Trace, 13
    Controller (State Management) The one StateMachine that starts with State Management, controls MachineFG and starts and stops the Agents. SM, 2.5
    Corruption The corruption of a system resource, such as a stack overflow or a bit flip; non-recoverable Core, 6.4
    CppImplementationDataType A data type with its C++ binding; its category selects the C++ form. Manifests, 6.4
    CurrentState The state a Function Group is in when a transition starts. EM, 8.1
    Daemon-based A functional cluster that is intended to be implemented with its own daemon process. Main page, Platform Overview, 4.2
    Data Identifier (DID) A UDS identifier of a data record that a tester can read or write, such as a software version. Diagnostics Part 1, 10.1
    Data type mapping PersistencyKeyValueDataTypeMapping: declares the previous and the current type of a key, so that the old value can be read during a migration. Persistency, 12.6
    Deadline Supervision A PHM supervision that checks that the time from a source to a target checkpoint lies between a minimum and a maximum. PHM, 7
    Design model Model content that describes the system across compute nodes and is exchanged between roles, often as a contract. Manifests, 1.2
    Determinism The property that the same inputs always give the same outputs, within a known, bounded time, every time. Platform Overview, 2.3.1
    Diagnostic Address The address under which a diagnostic server is reached. A machine can have one for all Software Clusters or one per Software Cluster. Diagnostics Part 1, 2.3
    Diagnostic Contribution Set DiagnosticContributionSet: the diagnostic configuration of one Diagnostic Server instance; Software Clusters reference it. Diagnostics Part 1, 2.3
    Diagnostic Conversation The state of the exchange between one diagnostic tester and one Diagnostic Server instance (session, security level, ongoing request), allocated at run time. Diagnostics Part 1, 6
    Diagnostic Event The atomic unit of fault detection in Diagnostic Management. Its status reflects the latest result of a diagnostic monitor; one or more events make up a DTC. Diagnostics Part 2, 2.1
    Diagnostic Extract (DEXT) The AUTOSAR model of the diagnostic behavior of an ECU, shared by the Classic and the Adaptive Platform; the configuration input of Diagnostic Management. Diagnostics Part 1, 2.8
    Diagnostic mapping A model element that connects a DEXT element, such as a DID or routine, to a port of an executable and a process. Diagnostics Part 1, 14.11
    Diagnostic Monitor The logic, usually in an application, that tests for a fault and reports the result to a diagnostic event. Diagnostics Part 2, 2.1
    Diagnostic Server instance One UDS server inside Diagnostic Management; there is one per Diagnostic Contribution Set. Diagnostics Part 1, 2.3
    Diagnostic Session A mode of a Diagnostic Conversation that unlocks diagnostic services, switched with DiagnosticSessionControl (0x10). Diagnostics Part 1, 2.5
    Diagnostic Trouble Code (DTC) A code that identifies a detected fault in the vehicle. Diagnostic Management stores it together with snapshot and extended data. Diagnostics Part 2, 8.1
    E2E Profile A standardized combination of E2E mechanisms and header layout, for example PROFILE_04. Secure Communication, 10.2
    E2E Protection Safety mechanisms that detect corrupted, lost, repeated or delayed data between sender and receiver. An E2E profile defines the exact mechanism. Secure Communication
    E2E State Machine The function that turns the history of E2E checks into the states VALID, INVALID, INIT or NODATA, using windows and thresholds. Secure Communication, 12
    ECU Electronic Control Unit: an embedded computer with at least one CPU and its peripherals in one housing, connected to vehicle networks, sensors and actuators. Platform Overview, 2.1
    ECU ID The identifier of the ECU or machine in log and trace messages, defined by DltEcu.ecuId. Log and Trace, 5.1
    Element (Persistency) A key-value pair of a Key-Value Storage or a file of a File Storage. Persistency, 2.1
    Error The inability of an assumed-bug-free API function to fulfill its purpose; recoverable; returned in Result or Future Core, 6.2
    Error code value The integer part of an ErrorCode, from the enumeration of its domain Core, 7.1
    Error domain The context of a set of error codes: identifier, name, messages, exception type Core, 7.3
    Error domain identifier The unique 64-bit number that identifies an error domain Core, 7.4
    ErrorRecoveryTable The rules of a StateMachine that map an error code to the StateMachine State to enter; it must contain an ANY entry. SM, 2.4
    Event (service element) A message that a service provider sends to all subscribed consumers. CM, 7
    Event Memory The part of Diagnostic Management that stores DTCs and their data. Diagnostics Part 2, 9.1
    Eventgroup On SOME/IP, a set of events and field notifiers that a client subscribes to together. Network Bindings
    Executable A program file with exactly one main() function. EM, 2.1, Manifests, 5.3
    Execution Budget In the Classic OS, the statically configured maximum execution time of a task or interrupt handler, enforced by timing protection. Platform Overview, 2.3.2
    Execution Dependency "Start me only after process X is Running (or has Terminated)." It controls order, not whether a process starts. EM, 6
    Execution Manifest The configuration of an Executable's processes: states, arguments, scheduling, dependencies, timeouts and more. EM, 4.1, Manifests, 8
    Execution State The state of a process as seen by the process itself. The only reportable value is kRunning. EM, 5.1
    ExecutionError A number (std::uint32_t) that identifies why a process failed. It is configured per process, with the default 1. EM, 14.6
    ExecutionErrorEvent The event that tells State Management which Function Group failed, together with its ExecutionError. EM, 14.6
    Executor An ara::core object that runs callables asynchronously in a thread-safe context Core, 11.12
    Explicitly aborting an Operation Immediately aborting an API call by calling ara::core::Abort, usually after a Violation Core, 10.3
    Failed Default Allocation The default memory allocation of the framework cannot satisfy a request; handled like a Non-Standardized Violation Core, 6.4
    Failure transparent A function that always succeeds: no errors, noexcept, no Result or Future Core, 2.5
    Field A service element that holds a value. Consumers can get it, set it and be notified when it changes. CM, 9
    File Storage A Persistency storage location in which a process can create files, like a directory without subdirectories. Persistency, 7
    Find service handle The ara::com::FindServiceHandle that identifies a running StartFindService search, used to stop it. CM, 6.4
    Fire-and-forget method A method without out arguments and without errors; the caller gets no answer. CM, 8.5
    Firewall The functional cluster that configures the filtering of network traffic according to rules from the Machine Manifest. IDSM and Firewall
    Forwarding header ara/core/core_fwd.h, which declares most ara::core types without defining them Core, 12.2
    Foundation The AUTOSAR standard that holds what the Classic and the Adaptive Platform have in common, such as the protocols and the glossary. Main page
    Foundation (standard) The AUTOSAR standard that contains the artifacts common to the Classic and the Adaptive Platform, such as protocols and common requirements, to ensure interoperability. Platform Overview, 1.2
    Freedom From Interference The guarantee that a faulty part of the system cannot disturb unrelated parts. EM, 11.1
    Freshness Value A counter or time stamp that makes each SecOC message unique in time and prevents replay. Secure Communication, 2.3
    Freshness Value Manager (FVM) The plug-in that provides and synchronizes SecOC freshness values; on the Adaptive Platform the platform extension apext::com::secoc::FVM. Secure Communication, 7.8
    Function Group A named group of processes that are switched on and off together. EM, 7.2, Manifests, 7.5
    Function Group State One mode of a Function Group, which defines the set of processes that run. EM, 7.2
    Functional address A diagnostic target address that addresses several servers at once. Diagnostics Part 1, 2.2
    Functional Cluster A logical group of platform functionality, such as Execution Management, with its own specification and API. Main page, Platform Overview, 5
    FunctionGroupPortMapping The manifest element that allows one State Management process to control one Function Group. EM, 12.6
    Getter The accessor of a field with which a consumer reads its current value (Get). CM, 9.3
    Global Supervision A group of supervisions of processes of one Function Group, with one aggregated status. PHM, 9.4
    Global Supervision Status The worst of the Elementary Supervision Statuses of a Global Supervision; additionally kSTOPPED. PHM, 9.2
    Graceful Degradation Continuing to operate with reduced functionality when errors occur, instead of failing completely. In the running example, ADAS.Degraded. SM, PHM
    Handle A {<SI>}Proxy::HandleType returned by service discovery; it identifies one found service instance and is used to create a proxy. CM, 6.5
    Health Monitoring Supervision of the software behavior for correct timing and sequence; the Foundation concept shared by the Classic and the Adaptive Platform. PHM, 2.6
    Hypervisor Low-level software that runs several virtual machines on one physical machine. Platform Overview, 4.3
    I-PDU A protocol data unit that carries one or more signals between ECUs. Network Bindings
    Identity and Access Management The framework that controls which Adaptive Applications may access which service interfaces and platform interfaces. Main page, IAM
    Identity Information The properties of an application on which access control decisions are based. IAM
    ImpactedByUpdate The marking of a StateMachine whose Function Groups are being updated; it blocks transition requests and recovery. SM, 2.7
    Implementation-defined behavior Behavior chosen and documented by the platform implementation; vendor-specific behavior is the same Core, 2.4
    Imposition time The point in the workflow at which a constraint must hold, for example IT_BefAraApiGen or IT_Mani. Manifests, 2.5
    Initial Process A process with management rights, for example to determine the exit status, over all processes of the Adaptive Platform. The OS shall allow starting EM as the Initial Process. Platform Overview, 7.4
    Initial State (StateMachine) The StateMachine State that a StateMachine enters when it is started without a parameter (ModeDeclarationGroup.initialMode). SM, 2.2
    Instance reference A reference that navigates from a base through context elements to a target in an instance tree. Written as -IREF. Manifests, 2.2, Manifests, 3.5
    InstanceIdentifier The binding-specific identifier of one service instance, ara::com::InstanceIdentifier. CM, 6.7
    InstanceSpecifier A path in the model that identifies a configured element, such as a port, from code. Example: /fusion/Root/CameraRPort. Manifests, 9.4, Core, 11.11
    Integrity The property that data has not been changed or destroyed in an unauthorized way. Cryptography
    Inter-Functional-Cluster (IFC) interface An interface that one functional cluster provides to other clusters. Not part of ARA and not a formal requirement; described in an annex of the SWS. Platform Overview, 6.2
    Intrusion Detection System The system that detects, records and reports security events. It consists of security sensors, the IdsM and the IdsR. IDSM and Firewall
    Intrusion Detection System Manager The functional cluster that collects security events, qualifies them by rules, and stores or forwards the qualified events. IDSM and Firewall
    Key-Value Storage A Persistency storage location that holds key-value pairs. Persistency, 6
    Language Binding How a service is presented to the programmer, for example as generated C++ proxy and skeleton classes. CM, 5
    Library-based A functional cluster whose interface library is linked into the application and communicates with the cluster directly. Platform Overview, 4.2
    Local cache The memory that Subscribe(maxSampleCount) reserves in the consumer for the samples of one event or field. CM, 7.3
    Log and Trace The functional cluster that lets applications and clusters send log messages to the network, a console or a file. Log and Trace, 1.1
    Log and Trace Extract The part of the model that describes the sources (DltEcu, DltApplication, DltContext) and the modeled messages. Log and Trace, 2.6
    Log channel A named output path of the DLT protocol, for example one Ethernet connection. Log and Trace, 2.5
    Log level The severity of a log message: Fatal, Error, Warn, Info, Debug or Verbose. Log and Trace, 9.1
    Log sink A destination of log messages: console, file, DLT network channel or ARTI, modeled as DltLogSink. Log and Trace, 11
    Logger The ara::log object that represents one context of one process; created by CreateLogger. Log and Trace, 2.3
    Logging backend The implementation of the LT protocol behind the ara::log library, for example a DLT daemon. Log and Trace, 1.4
    Logging client An external tool that receives and stores log messages and can control the ECU. Log and Trace, 2.8

    LogStream The temporary ara::log object that collects the arguments of one non-modeled message. Log and Trace, 7.8
    M out of N Redundancy with N copies of which at least M must be identical when read; the only redundancy type that can repair corrupted data. Persistency, 9.3
    Machine The environment one Adaptive Platform instance runs on: an ECU, a virtual machine or a container. EM, 2.1, Manifests, 7.3
    Machine Design The design-time placeholder of an Adaptive Machine in the system, the counterpart of the Classic EcuInstance. Manifests, 7.2

    Machine State A state of the Function Group MachineFG. EM, 7.3
    MachineFG The mandatory Function Group that controls the machine lifecycle. EM, 7.3

    Minimum Send Interval The configurable minimum time between two transmissions of one event, trigger, field update, method call, Get or Set. CM, 11.4
    Modeled message A log message whose static parts are defined in the model, so that only the dynamic parts are sent ("non-verbose" in DLT). Log and Trace, 8
    Modelled Process The manifest description of one way to run an Executable (the meta-class Process). EM, 2.1
    monitorMode Trusted-platform mode in which failed checks are logged, but software is still launched. EM, 12.3
    Multi-binding One proxy or skeleton class communicating over several transports or protocols, for example one instance offered over local IPC and SOME/IP. CM, 13.3
    Multicast Threshold The number of subscribers from which SOME/IP sends the events of an eventgroup by multicast instead of unicast. Network Bindings
    Named constructor A static noexcept function, usually Create, that constructs an object and returns a Result Core, 10.2
    Nested recovery A new error reported for a StateMachine while its previous recovery is still in progress. SM, 8.4
    Network Binding How a service is represented on a specific transport, for example SOME/IP or DDS: serialization and protocol. Network Bindings
    No rollback semantics A recoverability class: the failed call may have had side effects; invariants hold Core, 6.6
    Non-modeled message A log message that is built and sent completely at run time ("verbose" in DLT). Log and Trace, 7
    Non-reporting Process A process that does not report its Execution State and is considered Running immediately after creation. EM, 5.4
    Non-Standardized Violation A Violation specific to an implementation; ends with Abort or a non-ara::core exception Core, 6.3
    Non-verbose mode The DLT form in which a message carries only a message ID and its variable data. Log and Trace, 11.5
    Notifier The part of a field that notifies subscribers of value changes, like an event. CM, 9.5
    NRC Negative response code: the one-byte reason in a negative UDS response. Diagnostics Part 1, 2.1
    Off (state) The mandatory initial state of every Function Group. No processes run in it. EM, 7.2
    Operating System Interface The part of ARA that defines the operating system services available to Adaptive Applications (PSE51 and the C++ standard library), and the requirements on the operating system. Platform Overview, 7
    Operation Cycle A period, such as one drive cycle, that Diagnostic Management uses to evaluate and age DTCs. Diagnostics Part 2, 7.1
    OSEK OS The event-triggered automotive operating system with fixed priority-based scheduling, standardized as ISO 17356-3, on which the Classic OS is based. Platform Overview, 2.2
    OTA Client An Adaptive Application that connects the vehicle's update management to the backend. UCM
    P2, P2* Server response times of a diagnostic session: until the first response, and between response-pending messages. Diagnostics Part 1, 7.6
    Partial model The content of one ARXML file; it shall validate against the schema but need not satisfy all constraints. Manifests, 3.7
    Partial Network A subset of the nodes of a network that can be woken up and put to sleep independently of the rest. NM/TSync/RDS
    Partial SOME/IP Header The first 8 bytes of a SOME/IP header (Message ID and Length) in front of a signal-based PDU on Ethernet. Network Bindings
    Persistency user An Adaptive Application or a functional cluster that uses Persistency. Persistency, 2.3
    Physical address A diagnostic target address of exactly one server. Diagnostics Part 1, 2.2
    Planned Dynamics The principle that dynamic behavior is allowed during development but can be limited to defined ways for production. Main page, Platform Overview, 2.7
    Platform extension interface A standardized interface through which the OEM extends the platform: a callout, a callback or a plugin. Platform Overview, 3.5
    PLATFORM_CORE The category of the SoftwareCluster that carries MachineFG. There is exactly one per machine. EM, 7.3
    Policy Decision Point The logic of IAM that decides whether a request is allowed. IAM
    Policy Enforcement Point The logic of IAM that enforces the decision of the Policy Decision Point. IAM
    PortPrototype A port of a software component, provided (PPortPrototype) or required (RPortPrototype), typed by a port interface. Manifests, 5.2
    Pre-mapping Loading a process completely before it runs, to avoid demand-loading delays. EM, 11.4
    Process The running OS process that EM creates from a Modelled Process. EM, 2.1
    Process State The state of a process as tracked by EM: Idle, Starting, Running, Terminating, Terminated. EM, 5.1
    ProcessDesign The design-time stand-in for a process that will be defined in the Execution Manifest. Manifests, 5.4
    Processed Manifest A manifest converted into a platform-specific format for fast reading at startup. EM, 4.1, Manifests, 11.8
    Profile check status The result of the E2E check of one received sample, ara::com::e2e::ProfileCheckStatus. CM, 12.2
    Proxy (Service Proxy) The generated class with which a consumer uses a service, as if it were a local object. CM, 2.2
    PSE51 The minimal real-time POSIX profile. Adaptive Applications may use only this part of the OS API. Platform Overview, 7.2
    Qualified Security Event (QSEv) A security event that the IdsM has filtered and qualified by its rules. IDSM and Firewall
    Raw Data Stream Unstructured bytes exchanged with an external device, such as a sensor, over TCP, UDP or IEEE 1722. It is a functional cluster of its own, no longer part of Communication Management. NM/TSync/RDS
    Rebind The assignment behavior of Optional<T&> and Result<T&>: the object refers to the new target afterwards Core, 11.5
    Receive handler A callback that Communication Management calls when new event data, field notifications or triggers have arrived. CM, 7.5
    Recommended package The package name that the meta-model proposes for an element kind, for example ServiceInterfaces. Manifests, 3.2
    Recovery (Persistency) Best-effort restoration of a corrupted storage or element; the result may be current, outdated or initial data and must be validated. Persistency, 9.6
    Recovery notification The call of State Management's RecoveryHandler when a Global Supervision expires, and its configuration. PHM, 13
    Redundancy (Persistency) CRCs, hash values or copies that Persistency stores to detect and possibly repair corrupted data. Persistency, 9.1
    Registry An internal component that gives other clusters access to manifest information. Not used by applications. Platform Overview, 5.7, Manifests, 11.8
    Reporting Process A process that reports kRunning using ExecutionClient. This is the normal case. EM, 2.4
    RequestedState The target state of a transition. EM, 8.1
    Requirement ID The unique identifier of a requirement in a specification, such as [SWS_EM_01050]. Main page
    Reset (Persistency) Returning a storage or an element to the state after installation with the current target configuration. Persistency, 9.6
    ResourceGroup A group of processes that share a CPU limit and a memory limit. EM, 11.3
    Response Pending The NRC 0x78, sent by the server while it needs more time to answer. Diagnostics Part 1, 7.6
    Response time The time between a task becoming ready and generating its response, including all preemptions. Platform Overview, 2.3.1
    Rollback Returning to the previous software version after an update. UCM
    Rollback semantics A recoverability class: the failed call has no negative side effects; retrying is safe Core, 6.6
    RootSwComponentPrototype The root of the component hierarchy inside an Executable; its short name is part of every InstanceSpecifier. Manifests, 5.3
    Routine A function in the ECU that a tester starts, stops or queries with the UDS service RoutineControl. Diagnostics Part 1, 11.1
    Runnable (Runnable Entity) In the Classic Platform, a part of a software component that the RTE can start and that is executed in the context of an OS task. Platform Overview, 2.3.2
    Runtime Environment (RTE) In the Classic Platform, the generated layer between the application software components and the Basic Software. Platform Overview, 2.2
    S2R Hub The part of State Management that asks the S2R Satellites to enter or leave Suspend Mode and then tells the OS to suspend. SM, 2.8
    S2R Satellite An object in an S2R-Aware application that registers with the S2R Hub and is notified before suspend and after wake-up. SM, 2.8
    S3 timer Session timeout that returns a silent tester to the default session (5000 ms if not configured). Diagnostics Part 1, 8.1
    Safe Translation A Signal-to-Service translation that preserves end-to-end protection (safeTranslation). Secure Communication, 14.1
    Safety Element out of Context (SEooC) A safety element developed without a specific vehicle context, based on assumptions; at best, the architecture of the Adaptive Platform can be considered one. Platform Overview, 8.3
    SampleAllocateePtr The smart pointer to memory that a provider gets from Allocate() and hands over with Send. CM, 7.1
    SamplePtr The smart pointer, similar to std::unique_ptr, through which a consumer accesses one read-only sample. CM, 7.4
    ScheduleTable In the Classic OS, a statically defined set of expiry points that activate tasks or set events at fixed offsets. Platform Overview, 2.3.2
    Secure Channel A communication channel that provides at least integrity and authenticity, and authenticates at least one side. Secure Communication, Cryptography
    Secured I-PDU A message with SecOC authentication information: the authentic message, an optional freshness value and the authenticator. Secure Communication, 7.2
    Security Event An event related to the security of the ECU that should be reported for later analysis. IDSM and Firewall
    Security Level (diagnostics) A level of a Diagnostic Conversation unlocked with SecurityAccess (0x27) by a seed-and-key exchange. Diagnostics Part 1, 8.2
    Self-terminating Process A process that is allowed to exit on its own, typically a one-shot job. EM, 5.6
    Server A software entity that provides services to clients. CM, 2.1
    Service Functionality with a published interface and behavior that a provider offers to consumers. CM, 2.1
    Service contract version The majorVersion and minorVersion of a service interface; an incompatible change increases the major version. CM, 6.8
    Service Discovery The Communication Management mechanism with which applications find each other's services. It is the preferred way to sequence applications. EM, 6.6, CM, 6
    Service Instance One concrete provision of a service interface, with its own identity. CM, 2.1
    Service Instance Manifest The configuration of how service-oriented communication is deployed on the network, including E2E, security and logging settings. EM, 4.1, Manifests, 9, Network Bindings
    Service Interface The definition of a service: its events, methods and fields. CM, 2.1
    Service Registry The part of Communication Management with which providers register their services and consumers find them. CM, 3.3
    Service-based A functional cluster that offers its functions as services through Communication Management. Platform Overview, 4.2
    Service-Oriented Communication Communication in which partners are not fixed at design time but are discovered and bound at run time. CM, 1.1
    ServiceInstanceToPortPrototypeMapping The element that connects one port, in one process, to one service instance. Manifests, 9.3
    ServiceInterfaceDeployment The representation of a service interface on one transport, for example its SOME/IP IDs. Manifests, 9.1
    Session Handling Counting the Session ID of SOME/IP messages; active for requests, responses and segmented messages. Network Bindings
    Session ID The identifier of one instance of a software component that runs several times. Log and Trace, 5.5
    Setter The accessor of a field with which a consumer asks the provider to change its value (Set). CM, 9.4
    Shared handle ara::per::SharedHandle: the copyable owner of an open Key-Value Storage or File Storage. Persistency, 5.3
    Shared state The object shared by a Promise and its Future that holds the value or error Core, 9.1
    Short name The identifier of a model element within its name space; a C identifier, unique case-insensitively. Manifests, 3.2
    Signal A piece of data, such as the vehicle speed, that is exchanged in signal-based communication, typically in a PDU on CAN. Network Bindings
    Signal-Based Network Binding The binding of Communication Management that performs Signal-to-Service translation; variants Signal-Based SOME/IP, Signal-Based Static and Signal-Based IEEE1722 ACF. Network Bindings
    Signal-to-Service Translation The standardized mapping between signal-based communication and service-oriented communication, in both directions. Network Bindings
    Skeleton (Service Skeleton) The generated base class from which a provider implements a service and connects it to Communication Management. CM, 2.2
    SMControlApplication The project-specific application that decides which StateMachine transitions to request; it also decides whether an update is allowed. SM, 2.6
    Snapshot Record Environmental data, such as the vehicle speed, that Diagnostic Management stores when a DTC occurs. Diagnostics Part 2, 9.3
    Software Cluster The unit of deployment and update: a set of executables, manifests and data, which claims Function Groups. It is installed as one Software Package. The meta-class is SoftwareCluster. Running Example, 1.3, Manifests, 10.2, UCM
    Software Cluster Design The OEM's design-level contract for a Software Cluster (meta-class SoftwareClusterDesign). Manifests, 10.1
    Software Package The unit that UCM installs: one Software Cluster plus the metadata to install it. It is digitally signed. UCM, Manifests, 10.3
    SOME/IP An AUTOSAR protocol for service-oriented communication over IP, with its own service discovery (SOME/IP-SD). Network Bindings
    SOME/IP-TP The segmentation of large SOME/IP messages over UDP. Network Bindings
    SOVD Service-Oriented Vehicle Diagnostics, an ASAM standard for diagnostics over web technologies. Diagnostics Part 2, 2.7
    Stack An implementation of the Adaptive Platform standard by a platform vendor. Platform Overview, 1.3
    Standardized M1 model Model content published by AUTOSAR in the top-level package AUTOSAR, for example /AUTOSAR/StdTypes. Manifests, 2.1
    Standardized Violation A Violation defined by AUTOSAR, with a standardized DLT message Core, 6.3
    StartupConfig A reusable set of start parameters for a process. EM, 13.5
    State Management The functional cluster that decides which Function Group States are requested. EM, 7.4, SM, 1.1
    StateClientInterface The port interface of the R-port through which State Management controls one Function Group (status draft in R25-11). EM, 13.10
    StateDependentStartupConfig Links a process to a StartupConfig for a set of Function Group States, with dependencies and resources. EM, 13.4, Manifests, 8.2
    StateMachine (State Management) A configurable state machine of State Management that covers standard cases with little code. A project-specific application requests its transitions. SM, 2.2
    StateMachine State A state of a State Management StateMachine (a ModeDeclaration); entering it executes its ActionList. Not the same as a Function Group State. SM, 2.2
    Static Service Connection SOME/IP communication with pre-configured endpoints instead of service discovery. Network Bindings
    Storage header The header that a logging client adds in front of each stored DLT message. Log and Trace, 11.9
    strictMode Trusted-platform mode in which software that fails a check is never launched. EM, 12.3
    Subscription state The state of a subscription: kSubscribed, kNotSubscribed or kSubscriptionPending. CM, 7.2
    Supervised Entity A whole or a part of a software component type that is supervised; a collection of checkpoints. PHM, 2.1
    Supervised Entity Instance One occurrence of a Supervised Entity, identified by its port in an executable and its process. PHM, 5.5
    Supervised Process A process that PHM supervises. EM informs PHM about its lifecycle. EM, 5.9
    Supervision Mode A state of the machine or a Function Group in which supervisions are performed with a specific set of parameters. PHM, 12
    Support data value Optional vendor-specific data inside an ErrorCode; ignored by comparisons Core, 7.1
    Suspend-to-RAM (S2R) A low-power mode in which RAM keeps the system state while most of the machine is powered down, for a fast wake-up. SM, 2.8
    Target configuration Model content whose scope is mostly local to one compute node, usually created during integration. Formerly called "deployment". Manifests, 1.2
    Target Configuration version The version of the deployed content of a storage (PersistencyCommon.Version); it decides between installation, update and roll-back. Persistency, 2.5
    Task (OS) The smallest schedulable unit managed by the operating system; a thread in POSIX terms. Platform Overview, 7.10
    Termination handler The callback that ExecutionClient invokes, in a background thread, when SIGTERM arrives. EM, 5.5
    Temporary storage The in-memory working copy of an open Key-Value Storage; changes become persistent only with SyncToStorage. Persistency, 6.1
    Thread-safe Callable concurrently on the same object by several threads without synchronization by the caller Core, 12.6
    Threshold The minimum log level that a logger lets through. Log and Trace, 2.1
    Time Base A synchronized time, such as VehicleTime, that Time Synchronization offers to applications. NM/TSync/RDS
    Timing protection In the Classic OS, the run-time enforcement of statically configured execution budgets, lock budgets and minimum inter-arrival times. Platform Overview, 2.3.2
    Trace status The on/off switch for trace messages of a context, controlled by control messages. Log and Trace, 9.5
    Trace switch The compile-time routing of a modeled message to the logger, ARTI, both or nowhere, configured by TraceSwitchConfig. Log and Trace, 14.3
    TransitionRequestTable The rules of a StateMachine that map a requested value and the current StateMachine State to the next StateMachine State. SM, 2.4
    Transport fault condition A transport-related fault reported to a handler: sample rejected, deadline missed or sample lost. CM, 11.5
    Transport Protocol Handler A plug-in of Diagnostic Management that implements a UDS transport protocol such as DoIP. Diagnostics Part 1, 5.1
    Trigger A service element like an event, but without data. CM, 7.7
    Trust Anchor The root of trust, for example a public key in protected memory, from which all authenticity checks derive. EM, 12.1
    Trusted Platform A platform on which only software of verified integrity and authenticity runs. EM, 12.1
    UDS Unified Diagnostic Services, the diagnostic protocol of ISO 14229 that testers use. Diagnostics Part 1, 2.1
    Undefined behavior No guarantees at all, as in the C++ standard; not detected, unlike a Violation Core, 2.4
    Undefined Function Group State A Function Group state that is not one of the modelled states: during a transition, after a failed transition, or after a crash. EM, 10.3
    Unexpected Termination A process ended without a justified reason, for example without being asked to, or before it reported kRunning. EM, 2.5
    Unique handle ara::per::UniqueHandle: the move-only owner of an open file accessor. Persistency, 5.3
    Unrecoverable State EM's last resort: pre-cleanup, then terminate all processes, then post-cleanup. EM, 10.4
    Update Bit A bit in a PDU that indicates whether a signal was actually updated in this transmission. Network Bindings
    Update session The period, granted by State Management, during which UCM may change the software of the machine. UCM
    Update strategy What Persistency does with an existing element when a new configuration is deployed: keep existing, overwrite, or delete. Persistency, 2.6
    Uploadable element An element derived from UploadablePackageElement, which is uploaded to the Machine as part of a Software Cluster. Manifests, 2.4
    Vehicle Package A package, assembled by the OEM backend, that describes an update campaign across several ECUs. V-UCM processes it. UCM
    Vehicle Services Functional clusters that provide vehicle-level functions: V-UCM, the Automotive API Gateway and Remote Persistency. Platform Overview, 3.3
    Vehicle State Manager An OEM-specific application that controls the vehicle-level state and interacts with V-UCM during updates. UCM
    Vehicle Update and Configuration Management The functional cluster that coordinates software updates across all ECUs of a vehicle. Main page, UCM
    Vendor-specific error An error that an implementation returns in addition to the specified ones, in a vendor-specific domain Core, 7.6
    Verbose mode The DLT form in which a message carries type information, and optionally names and units, for each argument. Log and Trace, 11.6
    Violation A broken API contract, for example two ExecutionClient objects. It is logged, and the offending process is terminated. EM, 10.1, Core, 6.3
    Violation message The standardized fatal DLT message of a Standardized Violation Core, 15.3
    Watchdog A hardware or software timer that resets the system if it is not triggered in time. PHM triggers it. PHM, 14
    Worst-case execution time (WCET) The longest possible execution time of a task or interrupt handler. Platform Overview, 2.3.1
    Write-only-once Access mode, new in R25-11, that allows adding elements to a storage but never changing existing ones. Persistency, 2.8
